# WeatherApp

Консольное приложение на C# (.NET 8), которое получает текущую погоду для списка городов через API [wttr.in](https://wttr.in) и выводит статистику по странам.

## Что делает

1. Загружает список городов из файла `Cities.txt` в память и убирает повторы (без учёта регистра).
2. Для каждого уникального города запрашивает данные через `https://wttr.in/{City}?format=j1`.
3. Сохраняет результат в модель `WeatherData` с полями: город, текущая температура в °C, страна.
4. Выводит погоду по каждому городу, например: `Tokyo, Japan +18 °C`.
5. Группирует города по странам и выводит для каждой страны количество городов, среднюю, минимальную и максимальную температуру, например: `Japan — 3 cities, avg: +19 °C, min: +16 °C, max: +22 °C`.

Для работы с JSON используется только `System.Text.Json`, внешних пакетов нет.

## Запуск

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

```bash
dotnet run
```

По умолчанию читается `Cities.txt` из папки проекта (при сборке он копируется рядом с исполняемым файлом). Можно передать свой файл, по одному городу в строке:

```bash
dotnet run -- path/to/cities.txt
```

## Структура

| Файл | Назначение |
|------|------------|
| `Program.cs` | Чтение файла, вывод погоды и статистики по странам |
| `WeatherData.cs` | Модель `WeatherData` (город, температура, страна) |
| `WeatherService.cs` | Запросы к wttr.in и разбор JSON, до 3 повторов при ошибке |
| `TemperatureFormat.cs` | Форматирование температуры со знаком: `+18 °C` |
| `Cities.txt` | Список городов |

## Особенности

- Название города берётся из входного файла, а не из ответа API: wttr.in иногда возвращает ближайший район (например, «Лахта» для Saint-Petersburg).
- Если город не удалось получить, выводится ошибка, и программа продолжает работу с остальными.
- Средняя температура округляется до десятых, целые значения выводятся без дробной части.
